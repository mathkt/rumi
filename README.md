# 루미큐브 온라인

학생들과 함께하는 4인 루미큐브. 단일 HTML(`index.html`) + Firebase Realtime Database로 동작하고, GitHub Pages로 배포합니다.
Firebase 설정이 없어도 **"한 화면 연습"** 모드는 바로 쓸 수 있습니다.

## 방 만들 때 바꿀 수 있는 설정
| 설정 | 선택지 | 기본값 |
|---|---|---|
| 인원 | 2 / 3 / 4명 | 4 |
| 첫 등록 점수 | 없음 / 20 / 30점 | 30 |
| 차례 시간 | 60 / 90 / 120초 / 제한 없음 | 90초 |
| 전체 제한 시간 | 없음 / 20 / 30 / 40분 | 30분 |
| 시작 패 개수 | 10 / 14개 | 14 |
| 조커 | 없음 / 2개 | 2개 |
| 컴퓨터 난이도 | 쉬움 / 보통 / 어려움 | 보통 |
| 힌트 | 없음 / 3번 / 무제한 | 3번 |
| 시간 끝날 때 | 올바르면 자동 제출 / 그냥 넘김(공식) | 자동 제출 |
| 정리 못 끝낸 벌칙 | 1장 / 3장(공식) | 1장 |
| 반응 버튼 | 켜기 / 끄기 | 켜기 |

방장은 대기실에서 게임 시작 전까지 설정을 다시 바꿀 수 있습니다.

점수는 공식 규칙대로 계산합니다. 누가 패를 다 비우면 나머지는 남은 타일 합(조커 30)만큼 잃고 승자가 그 합을 얻습니다. 더미가 바닥나거나 시간이 끝나면 남은 합이 가장 낮은 사람이 이기고, 나머지는 그 사람과의 차이만큼 잃습니다. 같은 방에서 다시 하면 결과 화면에 누적 점수표가 쌓이고, 인원수만큼 판을 하면 라운드 우승자가 표시됩니다.

## 1. Firebase 연결 (처음 한 번)
1. Firebase 콘솔에서 프로젝트를 고르고 **Realtime Database**를 만듭니다(이미 있으면 그대로 사용).
2. **프로젝트 설정 → 내 앱 → 웹 앱**의 `firebaseConfig` 값을 `index.html` 맨 아래쪽 `window.FIREBASE_CONFIG` 안에 붙여 넣습니다.
   `databaseURL` 값이 꼭 있어야 합니다.
3. **Realtime Database → 규칙**에서 기존 규칙은 그대로 두고, `rummikub` 항목만 같은 단계에 추가합니다.
```json
{
  "rules": {
    "rummikub": {
      "rooms": { "$code": { ".read": true, ".write": true, ".validate": "$code.matches(/^[0-9]{4}$/)" } },
      "hands": { "$code": { ".read": true, ".write": true, ".validate": "$code.matches(/^[0-9]{4}$/)" } }
    }
  }
}
```
기존 프로젝트를 재사용할 때는 이미 있는 `"rules": { ... }` 안에 `"rummikub": { ... }` 부분만 끼워 넣으세요.

## 2. GitHub Pages 배포
1. 저장소를 만들고 이 폴더의 파일을 올립니다(필수: `index.html`).
2. 저장소 **Settings → Pages → Branch: main / (root)** 로 켭니다.
3. `https://<조직>.github.io/<저장소>/` 가 게임 주소입니다. 방을 만들면 **초대 링크 복사** 버튼으로 `?room=코드`가 붙은 주소를 학생들에게 줄 수 있습니다.

## 컴퓨터(🤖)
- 대기실에서 방장이 빈자리에 **🤖 컴퓨터 넣기**(또는 빈자리 모두 컴퓨터로)를 누르면 됩니다. 난이도는 방 설정의 **컴퓨터 난이도**(쉬움·보통·어려움).
- 컴퓨터 차례는 방장 화면이 계산합니다. 방장이 끊기면 남은 사람 중 번호가 가장 빠른 사람의 화면이 이어받습니다.
- 게임 중 학생이 나가면 방장이 **🤖 끊긴 자리 컴퓨터로**를 눌러 대신 두게 할 수 있고, 그 학생이 같은 이름으로 들어오면 돌려받습니다.
- 한 화면 연습은 기본이 **나 + 컴퓨터 3명**입니다.

## 수업 운영 팁
- 처음 하는 반: **첫 등록 20점 · 조커 없음 · 시작 패 10개** 로 시작하면 한 판이 짧고 규칙이 쉽습니다.
- 차시 안에 끝내려면 **전체 제한 시간 30분 이하**를 쓰세요. 끝나면 자동 정산됩니다.
- 학생이 새로고침·재접속해도 같은 기기에서는 자기 자리로 자동 복귀합니다. 다른 기기에서는 같은 이름으로 들어오면 끊긴 자리를 이어받습니다.
- 자리를 비운 학생은 시간이 지나면 자동으로 타일을 뽑고 넘어갑니다. 시간 제한이 없는 방에서는 방장이 **끊긴 사람 넘기기**를 누르세요.

## 알려진 한계
- 각자의 패는 별도 경로에 저장하지만, 개발자 도구를 쓰면 다른 사람의 패를 볼 수 있습니다(수업용 수준의 비공개).
- 끝난 방의 데이터는 자동으로 지워지지 않습니다. 가끔 콘솔에서 `rummikub/rooms`, `rummikub/hands`를 삭제해 주세요.

## 파일 구성과 개발
| 파일 | 역할 |
|---|---|
| `index.html` | 배포용 완성본 (아래 빌드로 생성) |
| `index.template.html` | 화면(HTML/CSS/JS) 원본 |
| `rk-engine.js` | 규칙 엔진: 세트 판정, 차례 검사, 점수, 타일 이동 |
| `rk-ai.js` | 컴퓨터 플레이어(쉬움·보통·어려움) |
| `rk-net.js` | 온라인 통신: 방·입장·시작·차례·시간초과·재접속·컴퓨터 자리 |
| `build.js` | 위 파일들을 합쳐 `index.html` 생성 |
| `fakedb.js` | 테스트용 가짜 DB |
| `*.test.js` | 테스트 |

```
node build.js                      # index.html 만들기 (원본을 고친 뒤 꼭 실행)
node rk-engine.test.js             # 규칙 엔진 테스트
node rk-ai.test.js                 # 컴퓨터 플레이어 테스트(자동 대국 포함, 약 1~2분)
node rk-net.test.js                # 온라인 통신 테스트(가짜 DB)
NODE_PATH=<playwright 위치> node shots.js            # 디자인 확인용 스크린샷(1366x768)
NODE_PATH=<playwright 위치> node ui.test.js          # 브라우저에서 드래그까지 점검
NODE_PATH=<playwright 위치> node ui-online.test.js   # 브라우저 2개로 온라인 흐름 점검
```
